# Infrastructure Module Map

## Scope
- Docker Compose production, host-Nginx staging, and development foundations for `api`, `web`, `worker`, `postgres`, `redis`, and optional container `nginx`.
- Nginx reverse proxy owns public HTTP entry, security headers, request size limits, and rate-limit foundation.
- PostgreSQL uses a named volume; upload/export storage uses shared named volumes mounted into API and worker containers.
- Backup and restore scripts are VPS-friendly shell wrappers around the Compose PostgreSQL service with custom-format dumps, restore confirmation, and retention pruning.

## Files
- `../compose.prod.yaml`: production service topology with only Nginx exposed to the host.
- `../compose.staging.yaml`: host-Nginx VPS override that exposes only web/API on loopback ports `3100`/`3101` and disables container Nginx by profile.
- `../compose.dev.yaml`: local container topology with explicit developer ports.
- `nginx/nginx.conf`: reverse proxy, health, headers, body limits, and rate-limit foundation.
- `../scripts/backup-postgres.sh`: compressed `pg_dump` backup foundation.
- `../scripts/restore-postgres.sh`: compressed/plain SQL restore foundation.
- `../scripts/check-production-infra.mjs`: static production infrastructure safety checks.
