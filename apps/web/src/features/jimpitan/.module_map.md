# Frontend Jimpitan Module Map

## Scope
- Implements tenant-aware Jimpitan collection operations for web: session list, mode-aware session creation, session detail, validation/rejection/cancel controls, checklist display, outstanding tracking, per-area progress, mobile house-by-house input, bulk-total input, optimistic item save with rollback, RBAC-aware actions, and tests.
- Excludes finance charts, public transparency pages, Telegram UI, analytics dashboards, payment gateway flows, and duplicated backend business rules.

## Files
- `api.ts`: same-origin `/api/backend/jimpitan/collections` adapter with tenant headers, item/bulk-total endpoints, and safe error wrapping.
- `hooks.ts`: TanStack Query hooks and scoped mutations for sessions, checklist, summary, outstanding rows, membership lookup, lifecycle actions, bulk total updates, and optimistic one-house item updates.
- `types.ts`: frontend Jimpitan response, collection mode, and payload contracts mirrored from backend DTOs.
- `collection-mode-workflow.ts`: selector for `PER_HOUSE`, `BULK_TOTAL`, and `HYBRID` UI workflows.
- `schemas.ts`: React Hook Form/Zod validation for session creation, bulk total input, and item input payloads.
- `workflow.ts`: pure lifecycle action, editability, progress, next-house, and formatting helpers.
- `membership-options.ts`: safe officer option fallback from active tenant session metadata.
- `components`: status badges, progress metrics, session cards, session form, lifecycle dialogs, mobile item panel, bulk total panel, and safe error text.
- `pages`: operational dashboard/session list, session detail workspace, and mobile collection workflow.
- `*.test.ts`: workflow, schema, and API adapter tests.

## Flow
1. App Router pages load feature page components under `/dashboard/jimpitan`.
2. Feature pages resolve active tenant and permission context from `TenantProvider`.
3. Hooks call `/api/backend/jimpitan/collections*` with `X-Tenant-Id`; the Next route handler attaches httpOnly backend credentials server-side.
4. Lifecycle actions remain UI-visible only when `workflow.ts` and permission context allow them; backend RBAC remains authoritative.
5. `PER_HOUSE` mobile item input saves one house per mutation, performs a scoped optimistic checklist update, rolls back on failure, then invalidates detail, summary, outstanding, and list caches.
6. `BULK_TOTAL` mobile/detail input saves only `totalAmount` and optional note; checklist and outstanding panels are hidden for those sessions.
7. Validation/rejection/cancel actions use confirmation dialogs and backend lifecycle endpoints; validated sessions render locked input state.
