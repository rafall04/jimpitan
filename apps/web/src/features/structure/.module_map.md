# Structure Feature Map

## Scope
- Implements tenant-aware frontend UI for Residents, Houses, and Areas only.
- Covers CRUD forms, detail sheets, search/filter/sort/pagination, archive/reactivate where backend contracts support it, resident-house assignment, occupancy status display, Telegram binding display, RBAC-aware actions, mobile card fallbacks, confirmations, loading/error/empty states, and tests.
- Excludes Jimpitan, finance, reporting, charts, Telegram bot UI, and fake production data.

## Files
- `types.ts`: backend response and payload contract mirrors for Residents/Houses/Areas.
- `schemas.ts`: Zod form schemas, payload mappers, and query string serialization.
- `api.ts`: browser API adapter that calls the same-origin `/api/backend/*` proxy with `X-Tenant-Id`.
- `hooks.ts`: TanStack Query list/detail hooks and mutation invalidation.
- `components/*`: forms, status badges, action rules, confirmation dialog, list shell, error message, and record sheet primitives.
- `pages/residents-page.tsx`: resident list/detail/create/update/archive/reactivate/house assignment UI.
- `pages/houses-page.tsx`: house list/detail/create/update/archive UI.
- `pages/areas-page.tsx`: area list/detail/create/update/archive UI.
- `*.test.ts(x)`: schema, API, action visibility, table, and badge tests.

## Flow
1. Dashboard route renders a feature page under `TenantProvider`.
2. Page composes list params from UI filters and active tenant context.
3. Hook calls `api.ts`, which sends same-origin requests to `/api/backend/{resource}` with the active `X-Tenant-Id`.
4. The Next proxy attaches httpOnly access tokens server-side and forwards only allowlisted resources to backend `/api/v1`.
5. Mutations invalidate tenant-scoped `areas`, `houses`, and `residents` query scopes because structure records affect each other.
6. Backend remains authoritative for tenant isolation, RBAC, archive rules, occupancy updates, audit logs, and Telegram binding validation.

## Safety Notes
- Browser code never reads backend bearer or refresh tokens.
- UI permission gates only hide unavailable controls; backend RBAC remains mandatory.
- House and area reactivation is not invented in the frontend because the backend exposes archive-only contracts for those resources.
- Archived houses and areas do not expose edit/archive controls; inactive residents expose reactivate only when the active role has resident update permission.
- Resident-house assignment uses the backend move endpoint and remains tenant-scoped through the proxy.
- Telegram binding is display-only in this UI; raw Telegram binding UUID edits stay out of the resident form and remain backend/bot-owned.
- Form IDs use UUID-v4 validation to match backend DTO constraints, and unexpected 5xx API details are not surfaced in toasts.
