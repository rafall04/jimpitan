# Frontend Finance Module Map

## Scope
- Implements tenant-aware Finance, Cash Ledger, Expense Approval, and private report export UI: dashboard, cash accounts, transaction categories, transactions, transaction detail, read-only ledger, mode-aware collection-to-finance posting contracts, approval queue, approval detail, CSV export lifecycle controls, RBAC-aware actions, and tests.
- Excludes public transparency pages, Telegram UI, payment gateway, advanced analytics, PDF/Excel generation UI, and backend financial rule duplication.

## Files
- `api.ts`: same-origin `/api/backend/finance`, `/api/backend/ledger`, `/api/backend/approvals`, private report summary adapters, and private report export adapters.
- `hooks.ts`: TanStack Query hooks and scoped mutations for accounts, categories, transactions, ledger rows, finance summaries, approvals, collection posting, and report exports.
- `types.ts`: frontend contract types mirrored from backend Finance, Ledger, Approval, report summary, and report export DTOs.
- `schemas.ts`: React Hook Form/Zod validation for account, category, transaction draft, reason, and collection posting payloads.
- `workflow.ts`: pure action visibility, immutable posted-state, approval decision, label, and currency helpers.
- `components`: badges, metrics, confirmation dialog, lifecycle action controls, safe error formatting, report export panel, and finance forms.
- `pages`: finance dashboard, accounts, categories, transactions, transaction detail, ledger, approvals queue, and approval detail pages.
- `*.test.ts`: workflow, schema, and API adapter tests.

## Flow
1. App Router pages load feature page components under `/dashboard/finance` and `/dashboard/approvals`.
2. Feature pages resolve active tenant and permission context from `TenantProvider`.
3. Hooks call same-origin `/api/backend/*` routes with `X-Tenant-Id`; the Next route handler attaches httpOnly backend credentials server-side.
4. Report export controls call `/api/backend/reports/exports`, show recent status, allow CSV download only after completion, and retry failed exports.
5. Lifecycle action visibility is local UX only; backend transaction, approval, ledger, export idempotency, and tenant rules remain authoritative.
6. Posting actions always use confirmation and backend idempotency support. Posted transactions render immutable; ledger rows render read-only.
7. Collection posting lists validated Jimpitan sessions with mode labels and posts through the dedicated source collection endpoint; duplicate posting is blocked by backend source uniqueness for `PER_HOUSE` and `BULK_TOTAL`.
