# Attachments Module Map

## Scope
- Owns image upload validation, local-volume object storage (S3-ready behind a port), attachment metadata rows, public image serving, and soft deletion.
- Consumed by ContentModule for cover/gallery images; designed to back other owner types (transactions, report exports, resident imports) later.
- Storage backend is selected by binding `STORAGE_PORT`; only `LocalDiskStorageAdapter` exists today (writes under `UPLOAD_STORAGE_PATH`).

## Files
- `attachments.module.ts`: wires `STORAGE_PORT` (LocalDiskStorageAdapter) + `ATTACHMENTS_REPOSITORY` (Prisma); exports AttachmentsService.
- `attachments.tokens.ts`: `ATTACHMENTS_REPOSITORY` + `STORAGE_PORT` tokens.
- `domain/attachment.types.ts`: upload command/file shapes, image reference, file-name sanitizer, public image-path builder.
- `domain/image-validation.ts`: pure mime allowlist (jpeg/png/webp) + magic-byte sniff + size cap.
- `infrastructure/storage.port.ts`: put/get/delete object-storage abstraction.
- `infrastructure/local-disk-storage.adapter.ts`: disk implementation with strict path-traversal containment under the storage root.
- `infrastructure/attachments.repository.port.ts` + `prisma-attachments.repository.ts`: attachment metadata persistence.
- `application/attachments.service.ts`: validate → store → record on upload; serve/list/soft-delete; rolls back stored bytes if the metadata write fails.
- `presentation/attachments.controller.ts`: `@PublicRoute` `GET /api/v1/attachments/public/:attachmentId` image serving (cache + nosniff headers).

## Safety
- Uploads are validated by content sniffing (not just declared mime), capped by `MAX_UPLOAD_BYTES`, stored under randomized object keys, and checksummed.
- Public serving only returns images whose owning post is PUBLISHED + PUBLIC.
- Deletes are soft (status DELETED + `deletedAt`); physical removal is best-effort after the row update.
