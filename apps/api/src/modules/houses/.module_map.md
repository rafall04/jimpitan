# Houses Module Map

## Scope
- Implements tenant-scoped `areas` and `houses` REST endpoints.
- Owns area route ordering metadata, house occupancy status, archive validation, RBAC decorators, Prisma persistence, and structure audit logs.
- Does not implement jimpitan schedules, collections, finance posting, reporting, or Telegram bot commands.

## Files
- `houses.module.ts`: module imports, controllers, services, and repository DI binding.
- `houses.tokens.ts`: repository provider token.
- `domain/houses.types.ts`: safe area and house response shapes.
- `application/houses.commands.ts`: area/house commands, query contracts, and audit request metadata.
- `application/areas.service.ts`: tenant-scoped area use cases and archive safety.
- `application/houses.service.ts`: tenant-scoped house use cases, area validation, and occupancy safety.
- `infrastructure/houses.repository.port.ts`: persistence port.
- `infrastructure/prisma-houses.repository.ts`: Prisma implementation and audit writes.
- `presentation/areas.controller.ts`: `/api/v1/areas` routes and RBAC metadata.
- `presentation/houses.controller.ts`: `/api/v1/houses` routes and RBAC metadata.
- `presentation/dto`: request/query validation and OpenAPI metadata.

## Flow
1. Controller resolves `CurrentUser`, validates DTOs, and passes correlation metadata.
2. Service uses only `actor.rtId` for tenant scope and validates area/house lifecycle rules.
3. Repository applies `rtId` plus `deletedAt: null` to all active reads and rechecks area assignment and occupancy state inside write transactions.
4. Area archive is rejected when non-archived houses still reference the area.
5. House archive is rejected when active residents still reference the house.
6. House `OCCUPIED` state is derived from active resident assignments; creating occupied houses or marking vacant houses occupied is rejected.
