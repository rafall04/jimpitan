# Finance Module Map

## Scope
- Implements cash account management, transaction category management, income/expense transaction drafts, validation/rejection/void/post lifecycle, mode-aware source collection posting for `PER_HOUSE` and `BULK_TOTAL`, audit logging, RBAC, tenant isolation, idempotency, and atomic ledger posting.
- Expense approvals, reports, public pages, payment gateway logic, and analytics dashboards are not implemented here; Telegram finance commands call exported finance services without bypassing lifecycle rules.

## Files
- `finance.module.ts`: module imports, controller/service registration, hook adapter export, and bot-facing service exports.
- `finance.tokens.ts`: repository and collection posting provider tokens.
- `domain/finance.types.ts`: cash account, category, transaction, ledger, balance, and source collection posting response shapes.
- `application/finance.commands.ts`: cash account, category, transaction, posting, and collection posting command/query contracts.
- `application/finance.service.ts`: aggregate finance facade boundary.
- `application/cash-accounts.service.ts`: cash account use cases and tenant-scoped not-found handling.
- `application/transaction-categories.service.ts`: category use cases and tenant-scoped not-found handling.
- `application/finance-transactions.service.ts`: transaction lifecycle, amount/account/category validation, immutable posted-state rules, and collection posting use cases.
- `infrastructure/finance.repository.port.ts`: persistence port for accounts, categories, transactions, ledger posting, balance, and source collection posting.
- `infrastructure/prisma-finance.repository.ts`: Prisma implementation for finance CRUD, lifecycle, idempotency, ledger posting, balances, mode-aware source collection posting, concurrency safety, and audit logs.
- `infrastructure/jimpitan-finance.hooks.ts`: hook adapter for validated collection posting.
- `presentation/cash-accounts.controller.ts`: `/api/v1/finance/cash-accounts` routes.
- `presentation/transaction-categories.controller.ts`: `/api/v1/finance/categories` routes.
- `presentation/finance-transactions.controller.ts`: `/api/v1/finance/transactions` routes.
- `presentation/dto`: class-validator and Swagger DTOs for finance payloads and queries.

## Flow
1. Controllers enforce Auth, Tenant, and Permission guards, then pass `CurrentUser` and request metadata.
2. Services use `actor.rtId` for all tenant scope and validate account/category/transaction lifecycle rules.
3. Repository appends ledger entries only when posting a validated transaction inside one serializable DB transaction with retry on serialization conflicts.
4. Ledger sequence generation uses tenant-scoped account version updates plus the unique `(cashAccountId, ledgerSequence)` constraint.
5. Jimpitan collection posting runs through the hook/interface boundary, rejects generic draft source attachment, uses paid item sums for `PER_HOUSE`, uses validated `totalAmount` for `BULK_TOTAL`, prevents duplicate `sourceCollectionId` posting, and audits mismatched replay attempts.
