# Jimpitan Module Map

## Scope
- Implements tenant-scoped Jimpitan collection sessions, collection mode contracts, officer assignment, route/area assignment, mobile checklist generation, item batch input, bulk total input, lifecycle submission, treasurer validation/rejection, cancellation, summaries, outstanding tracking, RBAC, and audit logs.
- Provides finance-ready and Telegram-ready hook interfaces. It does not create accounting journals, expense records, reports, or Telegram provider calls; Telegram bot input calls this module through `JimpitanService`.

## Files
- `jimpitan.module.ts`: module imports, controller, service, Prisma repository, and no-op hook DI bindings.
- `jimpitan.tokens.ts`: repository and hook provider tokens.
- `domain/collection-mode.types.ts`: `PER_HOUSE`, `BULK_TOTAL`, and `HYBRID` mode contracts plus default mode helper.
- `domain/jimpitan.types.ts`: safe collection, checklist, item, summary, outstanding, mode, and workflow event shapes.
- `application/collection-mode.policy.ts`: validation boundary for mode-specific item, bulk total, submit, and validate rules.
- `application/jimpitan.commands.ts`: collection commands, mode-aware list query contracts, and request metadata.
- `application/jimpitan.service.ts`: tenant-scoped workflow policy, mode checks, lifecycle checks, officer/area validation, duplicate prevention, ownership checks, item validation, bulk total validation, and hook dispatch.
- `application/jimpitan.service.spec.ts`: workflow, mode, tenant isolation, duplicate, validation, RBAC ownership, and hook decoupling tests.
- `infrastructure/jimpitan.repository.port.ts`: persistence boundary used by the service.
- `infrastructure/jimpitan.hooks.port.ts`: domain hook boundary for future finance and Telegram subscribers.
- `infrastructure/noop-jimpitan.hooks.ts`: no-op hook implementation until subscribers exist.
- `infrastructure/prisma-jimpitan.repository.ts`: Prisma persistence, serializable route/date create/update checks, conditional lifecycle updates, mode-aware checklist/total handling, item upserts, summaries, outstanding tracking, and audit writes.
- `presentation/jimpitan.controller.ts`: `/api/v1/jimpitan/collections` routes and RBAC metadata.
- `presentation/jimpitan.controller.spec.ts`: controller permission metadata tests.
- `presentation/dto`: class-validator and Swagger DTOs for create/update/query/items/bulk-total/submit/validate/reject/cancel payloads.

## Flow
1. Controller resolves `CurrentUser`, validates DTOs, and passes correlation metadata.
2. Service uses `actor.rtId` for all tenant scope and applies RBAC ownership rules for officer-owned workflows.
3. Create/update verifies same-tenant active officer membership and active route area, then repository rechecks inside serializable transactions.
4. Checklist generation loads active route houses and active primary residents, excluding archived areas/houses/residents.
5. `PER_HOUSE` uses checklist/item input and requires at least one item before submit/validate; `BULK_TOTAL` skips checklist items and requires a positive integer total before submit/validate. `HYBRID` remains schema/API foundation only.
6. Item batch upsert rejects duplicate houses in the payload, verifies route house and resident ownership, saves by `(collectionId, houseId)`, and recalculates paid totals only for item-based modes.
7. Bulk total input writes `totalAmount`, optional note, mode-specific audit data, and `IN_PROGRESS` state without creating `CollectionItem` rows.
8. Treasurer validation/rejection only accepts `SUBMITTED` sessions and uses conditional updates to prevent stale concurrent lifecycle writes.
9. Validation/rejection/submission emits hook events after persistence; finance ledger posting and Telegram bot input remain decoupled through service/module boundaries.
