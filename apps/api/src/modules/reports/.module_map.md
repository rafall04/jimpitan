# Reports Module Map

## Scope
- Implements tenant-scoped private reporting, ledger-derived financial summaries, mode-aware collection reports for `PER_HOUSE` and `BULK_TOTAL`, outstanding houses, per-area collection progress, expense category breakdown, cash flow, approval activity, audit activity, public transparency endpoints, and export engine foundation.
- Reports derive financial numbers from immutable `cash_ledgers` joined to same-tenant `POSTED` transactions only. Draft, rejected, voided, deleted, and non-posted transactions are excluded.
- Public endpoints resolve active RT codes and expose only public-safe totals, monthly finance summaries, public announcement metadata, and public announcements. Resident personal data, internal notes, audit logs, approval internals, and ledger row details are not exposed publicly.
- CSV export lifecycle is implemented for finance summary, monthly finance, collection summary, private ledger, private transactions, and public-safe transparency exports. PDF and Excel providers are interfaces only; no PDF/Excel file generation provider is implemented.

## Files
- `reports.module.ts`: module imports, controller/service registration, repository binding, and service export.
- `reports.tokens.ts`: repository provider token.
- `domain/reports.types.ts`: finance, collection, outstanding, approval, audit, public, snapshot, and export response shapes.
- `application/reports.commands.ts`: report query, public feed, export, date-range, and request metadata contracts.
- `application/reports.service.ts`: application validation, date-range limits, tenant delegation, public serializer safety, export request orchestration, CSV generation, stale queued CSV recovery, queued CSV worker processing, retry, download, and public CSV endpoints.
- `application/report-export.ports.ts`: queue/PDF/Excel interfaces and deterministic CSV serializer foundation.
- `application/report-export.engine.ts`: pure table builder for private and public-safe CSV export payloads.
- `infrastructure/reports.repository.port.ts`: persistence port for private reports, public transparency reads, and export requests.
- `infrastructure/prisma-reports.repository.ts`: Prisma adapter for ledger aggregation, mode-aware collection/outstanding reports, approval/audit summaries, public announcements, export idempotency, stale queued CSV recovery, queued CSV export claiming, and audit logs.
- `presentation/reports.controller.ts`: REST endpoints, public route metadata, RBAC metadata, and request metadata capture.
- `presentation/dto/report.dto.ts`: class-validator and Swagger DTOs for private reports, public feeds, monthly public finance, and export requests.

## Flow
1. Private routes use `AuthenticationGuard`, `TenantGuard`, and `PermissionGuard`; every private service call passes `actor.rtId`.
2. Financial reports query `cash_ledgers` with `(rtId, ledgerDate)` filtering and require the joined transaction to be same-tenant `POSTED`.
3. Finance summary cash balances use the latest ledger balance at or before the report `dateTo`, so historical summaries do not include later postings.
4. Collection performance defaults to `SUBMITTED` and `VALIDATED`; rejected, draft, in-progress, and cancelled collection amounts are excluded unless an explicit status filter requests them. `PER_HOUSE` totals come from paid items; `BULK_TOTAL` totals come from collection `totalAmount` without item counts.
5. Outstanding reports exclude inactive/deleted houses, inactive/deleted areas, and `BULK_TOTAL` sessions, and never return collection item notes.
6. Public routes are marked `PublicRoute`, resolve `rt.code` only when the RT is active and not deleted, and return safe serializers with totals and published announcements only.
7. Export creation validates filter JSON size/keys, normalizes date/month filters, writes a tenant-scoped `report_exports` row, replays matching idempotency keys, rejects mismatched replays, and writes audit logs.
8. CSV exports move through `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`, and `EXPIRED` API states; the schema still stores `QUEUED` internally and maps it to public `PENDING`.
9. Worker processing recovers stale `PROCESSING` CSV exports, claims queued CSV exports in small batches, marks processing idempotently, and preserves requested-user audit context.
10. Download and retry routes are RBAC-protected, tenant-scoped, and audited; public CSV routes are unauthenticated but use public-safe tables only.
11. CSV serialization quotes RFC-style cells and prefixes formula-like string cells to reduce spreadsheet injection risk.
12. Snapshot metadata records live query strategy and version because no persistent report snapshot table exists in the schema.
